# 01 · 开放权重与模型授权

`AI 通识` · `Open Weights & Licensing`

</div>

---
<!-- HERO:END -->

> **本篇回答**：「开源模型」到底开放了什么？为什么厂商愿意把最烧钱的东西免费放出来？License 条款有哪些实际约束？对端侧硬件来说，「模型授权」是怎么回事？

## 〇、先建立直觉：权重是什么

剥离技术黑话，用一个厨房类比：

- **算法架构**（如 Transformer）是「厨房的设计图」
- **训练代码**是「菜谱和烹饪流程」
- **训练数据**是「食材和采购清单」
- **权重（Weights）**是厨师经过千万次试做后，熬出来的那锅**「秘制高汤」**

训练一个前沿模型要消耗数百万到数千万美元的算力，产出就是这一份权重文件。「开放权重」，就是把这锅高汤直接（或附带条件地）公开给所有人。

## 一、概念辨析：「开放权重」不等于「完全开源」

这两个概念经常被混用，但在商业和法律上有本质区别：

| 维度 | 完全开源（True Open Source） | 开放权重（Open Weights） | 闭源 API |
|---|---|---|---|
| 权重文件 | ✅ | ✅（`.safetensors` / `.gguf` 等） | ❌ |
| 推理代码 | ✅ | ✅ | ❌（只给接口） |
| 训练代码 | ✅ 完整 | 通常不给 | ❌ |
| 训练数据 | ✅ | ❌（核心机密） | ❌ |
| 你能做什么 | 完整复刻训练过程，甚至改进它 | 部署、微调，但**无法从零复刻** | 只能调用 |
| 代表 | OLMo、早期 BERT | Llama、Qwen、Mistral 等绝大多数「开源大模型」 | GPT 系列、Claude |

要点：目前市面上绝大多数被称为「开源」的大模型，严格意义上都是**开放权重**——你能用、能微调，但配方（数据与训练细节）仍在厂商手里。

## 二、商业逻辑：为什么把最烧钱的东西免费放出来

### 2.1 抢占生态标准

当权重开放后，全球开发者会基于它做二次开发。工具链、分词器、微调流程、部署脚本逐渐都适配了这一家的架构——模型架构成为「事实标准」。生态建立后，即便竞品在单点效果上更好，迁移成本也会把用户留在原生态内。

### 2.2 社区反哺与竞争防御

开放权重相当于获得了大规模的社区协作：量化适配（让模型在手机/PC 上跑起来）、垂直领域微调、问题反馈，都由社区完成。同时，免费可用的开放权重会直接压缩闭源 API 的溢价空间——这是对闭源阵营的竞争手段（Meta 开放 Llama 的公开动机之一）。

### 2.3 算力与服务变现

权重免费，但运行权重需要算力。云厂商把开放权重模型集成进云平台，用户免费下载模型，但规模化推理仍需购买 GPU 实例或托管服务——变现发生在算力与企业级服务层，而非权重本身。

## 三、License：开放权重的协议约束

开放权重不等于可以随意商用。厂商通过许可证控制商业边界，主流分三档：

| 档位 | 代表协议 | 核心规则 | 典型代表 |
|---|---|---|---|
| 宽松商用 | Apache 2.0、MIT | 自由使用、修改、商用，保留版权声明即可 | Qwen3 系列全线（Apache 2.0）、Mistral 部分模型 |
| 商业防御 | Llama Community License | 允许免费商用，**但月活超 7 亿须向 Meta 单独申请授权**；且禁止用输出训练竞争模型 | Llama 系列 |
| 学术/非商用 | CC-BY-NC 等 | 仅限研究与非盈利；商用须另购商业授权 | 部分研究机构模型、厂商「引流版」模型 |

两个容易踩的坑：

1. **同一厂商不同代际协议可能不同**：如 Qwen 早期版本（Qwen-7B/72B 等）曾使用自定义协议（含月活 1 亿的商用申请门槛），Qwen2 起大部分型号转为 Apache 2.0，Qwen3 系列全线 Apache 2.0。**选型时按具体模型的 LICENSE 文件为准，不能按品牌印象**。
2. **「防巨头」条款针对的是平台级玩家**：7 亿 MAU 门槛对绝大多数硬件厂商不构成约束，其设计目的是防止大型科技公司直接利用成果与授权方核心业务竞争；但「禁止用输出训练竞争模型」这类条款对做自研模型的团队有实际影响。

## 四、对端侧硬件的含义：权重与「端模型授权」

这是本仓库读者最需要理解的部分。云端和端侧的商业结构完全不同：

- **云端**：权重开放，用户仍需为算力付费——厂商的收费点保得住
- **端侧**：硬件和算力都是设备厂商自己的。如果端模型权重以明文文件（`.onnx` / `.gguf` 等）交付，意味着——
  1. **授权费难以约束**：拿到权重文件即可在任意设备上部署，合同之外的使用难以技术性阻止
  2. **逆向与蒸馏风险**：权重可被分析网络结构，或通过知识蒸馏将能力迁移到第三方小模型

因此端侧商业模型的常见交付姿势：

| 做法 | 说明 |
|---|---|
| 核心权重封闭交付 | 商业模型封装在加密 SDK 内，或固化在芯片中（黑盒交付），按设备/出货量计授权费 |
| 基础版权重开放引流 | 开放一个精度或功能受限的基础版（宽松协议），建立开发者认知；工业级精度与低功耗优化走闭源商业版 |
| 端云协同 | 端侧只部署轻量模型（如任务路由/预筛），复杂任务调用云端付费 API——收费点从「权重授权」转移到「云端用量」 |

理解了这一点，就能看懂行业里「端模型授权为什么贵」「为什么有的方案商坚持 SDK 黑盒交付」「为什么端云协同在商业上成立」这三个高频问题——它们都是同一个资产保护逻辑的不同解法。

> 模型规格与端侧芯片的对应关系（什么芯片跑得动什么模型），见下一篇 [02 · 模型规格与芯片载体](./02-model-size-chips.md)。

## 五、给 AI 硬件从业者的检查清单

选用开放权重模型进产品前，过一遍：

1. **看具体模型的 LICENSE 文件**（不是品牌口碑）：是否允许商用、有无 MAU 门槛、是否限制输出用途
2. **确认「开放」的范围**：只有权重，还是含训练细节？影响你未来自训/换代的可能性
3. **端侧部署时明确交付形态**：明文权重 or 加密 SDK？合同里授权范围按什么计（设备数/出货量/年限）
4. **微调后的归属**：基于开放权重微调出的衍生模型，License 对其分发有何要求
5. **留证**：下载时的 LICENSE 版本存档——协议可能随版本变更，纠纷时以当时版本为准
