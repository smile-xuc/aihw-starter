# 05 · 蒸馏：小模型如何「学」大模型

`AI 通识` · `Distillation`

</div>

<!-- HERO:END -->

> **本篇回答**：蒸馏和量化有何不同？硬件厂商何时需要自研小模型 / 买蒸馏模型？和「端模型授权」怎么拼在一起看？
>
> 建议先具备：[02 · 模型规格与芯片](./02-model-size-chips.md)（小模型放得下吗）、[03 · KV Cache 量化](./03-kv-cache-quantization.md)（量化是另一条压缩线）。授权边界见 [01](./01-open-weights.md)。

## 〇、先建立直觉：大厨带学徒

回到 [01 篇](./01-open-weights.md) 的厨房隐喻：权重是「秘制高汤」。

- **量化**：同一锅高汤，换小瓶子装——浓度（精度）变了，配方没变。
- **蒸馏**：大厨（教师模型）带着学徒（学生模型）做成千上万道菜；学徒学会的是**判断与口感近似**，不是把高汤原封搬走。学徒饭量小（参数少），能进小厨房（端侧），但很难在所有菜上达到大厨水平。

所以：蒸馏解决的是「**能力迁移到更小载体**」；量化解决的是「**同一模型存得更省、跑得更省带宽**」。二者常叠用，但不是一回事。

## 一、蒸馏 vs 量化 vs 剪枝

| | **蒸馏 Distillation** | **量化 Quantization** | **剪枝 Pruning** |
|---|---|---|---|
| 压的是什么 | 能力 / 行为分布（软标签、轨迹、偏好） | 数值精度（FP16→INT8/INT4…） | 结构稀疏（减连接、减专家） |
| 何时做 | 训练或专有后处理流程 | 部署前离线，或推理期在线（如 KV） | 训练/压缩流水线 |
| 产出 | **另一个更小的模型** | **同一架构的低比特权重或缓存** | 更瘦的同族网络 |
| 硬件直觉 | 「换个更小的大脑」 | 「同一大脑用更粗的字记笔记」 | 「砍掉不常用的回路」 |
| 本仓库落点 | 本篇；端侧路由/兜底 | [02](./02-model-size-chips.md) 权重；[03](./03-kv-cache-quantization.md) KV | 选型时偶见，不展开 |

目的都像「更小更能跑」，机制不同：**不要**对方案商说「我们量化一下当蒸馏」，也不要指望「INT4 一下就有垂直领域人格」。

## 二、硬件场景里蒸馏常用在哪

| 用途 | 典型规格直觉 | 为什么蒸馏 |
|---|---|---|
| **端侧意图路由 / 预筛** | 0.8B–2B 档 | 只要「要不要上云 / 走哪条技能」，不必旗舰全知 |
| **弱网 / 离线兜底话术** | 同上 | 云断了仍能短答，体验不崩 |
| **垂直领域** | 小到中模型 | 儿童话术安全边界、会议纪要风格、行业术语 |
| **人格 / 风格近似** | 视产品 | 用教师输出或语料把「说话方式」迁到可商用小模型；启发见 [talk-to-fengge · 女娲 Skill 蒸馏](../solutions/by-solution/04-talk-to-fengge.md)（架构启发，非训练教程） |

不做蒸馏的常见替代：直接买云 API（见 [04 · Token 与计费](./04-token-billing.md)）、用开放权重小模型 + 提示词、或买方案商加密 SDK 里的端侧模型（见 [01](./01-open-weights.md) 端模型授权）。

## 三、商业与授权：蒸馏不是「免费复制旗舰」

三块钱以外的约束：

1. **License**：部分开放权重协议**禁止用模型输出训练竞争模型**（如 Llama 社区许可中的相关条款）。用闭源 API 输出大规模蒸馏，还可能触碰服务条款。选型时回到 [01](./01-open-weights.md) 的 LICENSE 检查，而不是品牌印象。
2. **数据**：用户对话能否进训练集？儿童 / 家居场景默认应按最小化与脱敏设计；合同里写清数据用途。
3. **买 vs 自做**：
   - **买端侧专用小模型 / SDK**：交付快、授权边界清楚，但黑盒、换芯成本高。
   - **自蒸馏 / 微调**：可控、可沉淀数据资产，但要算标注/合成数据、评测集、合规与持续迭代人力——往往贵在工程，不在一次 GPU 账单。

端侧权重明文交付难收费、易被再蒸馏——这是 [01](./01-open-weights.md) 第四节同一逻辑；蒸馏既是你压缩成本的手段，也是你资产被迁走的风险面。

## 四、和端云怎么拼

蒸馏出的小模型，默认落在 [06 · 端云协同](./06-edge-cloud.md) 的 **「端侧预筛 / 路由 / 兜底」** 槽位，而不是取代云端旗舰：

```
端侧小模型（蒸馏/专用）──► 意图、安全、离线短答
         │
         └── 复杂理解 / 长上下文 / 多模态推理 ──► 云端大模型（按 token 计费）
```

[02](./02-model-size-chips.md) 的规格表决定「端上塞得进哪一档」；[04](./04-token-billing.md) 决定「什么流量值得上云」。蒸馏只是把端侧那一格填聪明一点。具体栈见 [by-solution/06 端侧混合](../solutions/by-solution/06-edge-hybrid.md)；切分原则见 [06 · 端云协同](./06-edge-cloud.md)。

## 五、对本仓库各品类意味着什么

| 品类 | 落点 |
|---|---|
| 🧸 玩具 / 🪴 桌宠 | BOM 极低 → 端侧多为 VAD；若有离线短答，才是 0.x–2B 蒸馏槽位 |
| 🎧 AI 耳机 | 本地可做唤醒与指令分类；同传/理解仍在云，见 [06-ai-earphone](../solutions/by-category/06-ai-earphone/) |
| 🤖 Agent 硬件 | 盒子内存够时，intent-router 小模型很值钱，见 [04-agent-hardware](../solutions/by-category/04-agent-hardware/) |
| 📷 IPC | 事件预筛可用小视觉/规则；复杂 Caption 上云，未必需要 LLM 蒸馏 |
| 🦾 具身 | 端侧策略/安全层与云端 VLA/规划分工；蒸馏对象通常是策略头而非整网旗舰 |

## 六、给 AI 硬件从业者的检查清单

采购或立项蒸馏相关能力前，问清：

1. **教师模型是谁、协议是否允许**用其输出训练可商用学生模型
2. **训练数据是否含用户对话**；留存、脱敏、未成年人条款如何约定
3. **评测集**：通用榜 + 你们场景集（安全拒答、方言、打断）是否都有数
4. **交付形态**：明文 GGUF/ONNX，还是加密 SDK；换芯片谁负责适配
5. **和量化的边界**：学生模型上端时权重量化几 bit、KV 精度多少（回扣 02/03）

本篇**不提供**可复现的竞品蒸馏步骤或训练代码；通识与选型问题清单到此为止。
