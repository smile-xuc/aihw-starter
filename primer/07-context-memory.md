# 07 · 上下文与记忆：窗口里的「现在」与跨会话的「记得你」

`AI 通识` · `Context & Memory`

</div>

<!-- HERO:END -->

> **本篇回答**：context window 和「长记忆」是不是一回事？KV cache、会话历史、摘要、画像库各解决什么？硬件产品怎样用最少成本做出「它还记得我」？
>
> **建议先读**：[03 · KV Cache 量化](./03-kv-cache-quantization.md)（窗口变贵的物理基础）。弱依赖：[04 · Token 与计费](./04-token-billing.md)（记忆注入会烧输入 token）。

## 〇、先建立直觉：课桌与抽屉

- **Context window（上下文窗口）**：课桌上摊开的讲义——模型「此刻看得见」的全部内容，**有限**；越摊越多，草稿纸（KV cache）越厚，显存与**输入计费**一起涨。
- **长期记忆**：抽屉里的便签——可以很小、可检索、可过期、可脱敏；下次上课只把相关几张抽出来放回桌面。

营销话术里的「百万上下文」和「永久记住你」常被混成一句。工程上它们是两层系统：一层是推理窗口，一层是产品数据。

## 一、概念拆开

| 概念 | 是什么 | 不是什么 |
|---|---|---|
| **Context window** | 单次推理可见的 token 上限 | 不等于跨月记忆 |
| **KV cache** | 窗口内中间结果的草稿纸 | 不是业务数据库 |
| **聊天记录全量重放** | 把历史原样塞回输入 | 默认解；又贵又吵 |
| **摘要** | 压缩后的「今天/本周发生了什么」 | 完整笔录 |
| **用户画像** | 结构化字段（名字、偏好、禁忌） | 自由文本堆砌 |
| **RAG 知识库** | 产品知识 / 说明书检索 | 私人记忆；权限与更新节奏不同 |

一句话：**窗口解决「现在」；记忆系统解决「跨会话的你」；知识库解决「关于世界/产品的事实」。**

## 二、工程分层（从便宜到贵）

对齐玩具方案与 Omni Host 的既有说法，建议四层：

| 层 | 内容 | 成本直觉 | 体验贡献 |
|---|---|---|---|
| **L0** | 当轮 KV / 窗口内消息 | 随轮次与模态涨；Realtime 音频进窗即计费 | 「这句接得上」 |
| **L1** | 上轮会话回填（短 JSON/要点） | 最便宜的「记得」 | 「你还记得我们刚聊完」 |
| **L2** | 每日/每周摘要（小模型离线批） | 玩具侧量级常 **&lt; 0.01 元/台/天**（flash 日批假设，见 [03-toys 方案 §6.1](../solutions/by-category/03-toys-companion/02-solution.md)） | 「隔天还记得」 |
| **L3** | 结构化画像（业务库） | 存储与合规成本为主；注入时按字段计 token | 黏性与迁移成本；厂商资产 |

推荐路径：**先做 L1，再 L2，最后 L3**。不要一上来把完整聊天记录塞进 system prompt。

```
每轮对话 → L0 窗口内上下文
         →（会话结束）落盘
下次开聊 → L1 上轮要点回填
夜间/空闲 → L2 小模型摘要
画像管道 → L3 结构化字段更新
建会话时 → instructions 预留记忆槽位，再注入 L3+L2（短）
```

玩具金样板：[03-toys-companion/02-solution · 第六节](../solutions/by-category/03-toys-companion/02-solution.md)；Realtime 宿主槽位：[Omni Runtime Host · 记忆管道](../solutions/by-solution/01-qwen/omni-realtime/README.md)。人格 + 可选记忆的架构启发：[talk-to-fengge](../solutions/by-solution/04-talk-to-fengge.md)。

> demo 目录若规划 `memory-layer/`，以品类 demo README 为准；**计划中的路径不要写成已可跑**。

## 三、成本与隐私

- **成本**：每多注入一段摘要/画像 = 额外输入 token（[04](./04-token-billing.md)）。日批摘要用 flash 档离线跑，通常远小于实时对话费；实时链路上做重摘要则又贵又堵。
- **反例 · IPC**：Caption 场景常**关闭**长期记忆 / 知识库 / 对话承接——降低延迟与成本，也减少家居视频语义留存面。见 [01-ipc/02-solution](../solutions/by-category/01-ipc/02-solution.md)。
- **儿童 / 家居**：脱敏、最短留存、家长授权；陪伴产品须遵守拟人化互动相关合规边界（玩具方案第六节已提示）。画像是资产也是责任。

## 四、Realtime 特殊点

音频 Realtime：**进入上下文即计费**（静默若未在端侧挡住，同样烧钱）。因此：

1. **记忆管道离线**——抽取、摘要、画像更新不要堵在实时 WebSocket 上。
2. **逼近窗口上限前主动压缩**——用短文本「上轮会话」替换堆积的音频历史（Omni 文档中的成本策略）。
3. **场景分流**——闲聊走 Realtime；长故事/纪要切文本链路再 TTS，两边共用同一套 L2/L3。

## 五、对本仓库各品类意味着什么

| 品类 | 记忆策略 |
|---|---|
| 🧸 玩具 / 🪴 桌宠 | L1→L3 是「活人感」与订阅叙事核心；摘要日批控成本 |
| 🤖 Agent / Omni 宿主 | instructions 预留槽位；L1 回填性价比最高 |
| 📷 IPC | 默认少记忆或不记忆；事件与检索另算（OSS/业务库） |
| 🎧 耳机 / 🎙️ 录音 | 同传偏会话内；会后纪要是另一条离线摘要链，勿与同传配额混用 |
| 👓 眼镜 / ⌚ 手表 | 窗口短、上云为主；跨会话记忆更依赖手机/云账号侧 |

## 六、给 AI 硬件从业者的检查清单

1. **先 L1 回填，再谈画像**——用最小注入验证「记得」的体感
2. **instructions 预留记忆槽位**——后期硬塞会撕整份提示词
3. **禁止默认全量聊天记录进 system**——摘要 + 结构化字段
4. **算注入 token**：画像字段上限、摘要字数上限写进产品规格
5. **分场景开关**：IPC / 企业会议默认关；陪伴默认开且可用户清除
