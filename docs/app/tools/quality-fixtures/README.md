# 二十例业务质量验收输入

准备日期：2026-10-05。所有用例均为 **未真实运行**。本目录的输入与事实标准用于评价模型结果；mock 通过只表示界面与协议流程可操作。

[cases.json](cases.json) 包含 8 个照片用例、8 个录音用例、4 个仅摘要阶段用例。V01/V02/M01/M02 延续 [质量验收包](../../QUALITY_ACCEPTANCE.md)，V01 在本集使用照片＋文字，原验收包 V01 的照片＋语音仍单独保留；两种输入条件分别记录。

- V01–V08：复用公开合成菜品图，覆盖识别、解释、无可读文字的 OCR/翻译、餐厅/价格/品牌/精确营养等画面未知信息。它们没有覆盖清晰多语种文字的正向 OCR/翻译质量，后续需补专门图片。
- M01–M08：原短会、非会议问句、议题/报价/风险/结尾片段、数字静音、双声道复制。剪辑与声道复制取自仓内合成音频，不是真实会议。原素材出处见 [samples/README](../../../../solutions/by-category/07-recorder/demo/bailian/samples/README.md)；剪辑、时长、声道及本机 FFmpeg 版本见 [provenance.json](provenance.json)。编码填充允许少量时长差异。
- S01–S04：本目录人工编写的虚构转写，覆盖提议未拍板、数字/相对日期、后来明确的结论、转写中的指令注入。仅检查摘要阶段，不经过 ASR；时间未知保留 `null`。

## 执行与记录

先用下面命令生成一个全新报告目录；命令没有网络调用，也不读取 Key。

```bash
node docs/app/tools/prepare-quality.mjs --out /tmp/aihw-quality-new
```

V/M 用例在相应网页体验里选择给定素材并使用固定问题，真实运行时由用户确认计费。`asset` 相对 `docs/app/`，可以从源码或公开站点取用；6 份新增录音位于 `audio/`。S 用例提供 `S01-request.json` 等请求体供受控摘要阶段验证，真实运行仍需要明确地域、凭证和费用上限。

每次尝试填写 `checklist.json`，保存脱敏 trace 并填写其文件位置；失败和重试分别记录，不能用最好的一次覆盖前一次。ASR 与摘要分开归因；来源 ID 合法、指向相关原句、事实正确三项分开判断。M07 静音的正确拒识可以内容通过，接口失败/计费仍如实记录。

20 个用例不等于 20 次模型请求：录音一般包含转写和总结，照片可能另有播报。费用未知保持未知，账单另外核对；这一清单不替代既有成本 runner 的预算约束。报告与导出不保存 Key、请求头、签名地址或原始私人媒体。

修正测试：查看来源 → 修改负责人/期限 → 保存 → 复制/下载/导出 → 重开历史 → 恢复 AI 原值。修正不再次调用模型；来源关联由模型生成，不因页面存在链接就自动判为事实正确。
