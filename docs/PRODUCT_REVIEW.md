# AIHW Starter 产品走查

日期：2026-10-04。范围：官网首页、体验广场各级页面、实时交互方案页、TurboQuant 学习页；包含手机、Pad、桌面、键盘、错误状态与离线使用。

## 产品关系

官网负责说明项目价值与选择方向，体验广场让用户看样本、用自己的素材验证、核对成本，方案与学习文章帮助理解实现。它们属于同一产品，应始终让用户知道自己在哪里、接下来能做什么、如何回到官网。

九个品类是商业化方向；品类内项目分别说明开发者用途和商业交付，两者可以重叠。本仓的回放、参考实现和真实调用验证进度单独展示，不把品类统一降格为 demo，也不把样本回放当作已验证产品。

## 发现与修复

| 实际问题 | 用户影响 | 本轮处理 |
|---|---|---|
| 广场进入后缺少官网出口 | 品类、硬件、设置都像独立站点，深链接进入后难以了解整个项目 | 静态全局栏显示 AIHW Starter／体验广场，始终提供官网链接；数据加载失败和禁用 JavaScript 也能返回 |
| 配置 Key 只有保存返回 | 用户暂时没有 Key 时要自行找回体验 | 增加「暂不配置，返回体验」，保留内存中的照片、录音与问题，不触发模型请求 |
| 「跑测」导航实际打开账本 | 入口名称让人误以为会直接执行测试 | 改为「成本」，保留账本与计划导出功能 |
| 手机品类页的体验入口在长项目列表之后 | 看项目与动手体验之间切换成本高 | 增加项目、体验、资料三个页内跳转；尊重减少动效设置，目标避开固定栏 |
| 无效地址会回退到错误内容，异常编码可能中断路由 | 链接错误变成难以解释的页面行为 | 校验路径、品类、玩法和硬件项目，显示统一未找到页面与恢复入口 |
| 「缓存全部」只下载样本，漏轨迹和输出音频，还可能把失败当成功 | 首次离线打开从未看过的体验没有结果 | 从注册表及轨迹收集完整依赖，检查响应与实际缓存写入；逐项报告失败，支持重试 |
| 缺少回放时提示「素材或提问已更改」 | 用户没有修改输入却收到错误指引 | 明确提示示例暂不可用，提供联网重试与缓存入口 |
| 离线点击官网会离开可用的 PWA | 用户落入浏览器断网页 | 保留真实链接；断网时普通激活提示需联网，并留在广场；官网不宣称支持离线 |
| TurboQuant 两张宽表在手机被裁切 | 最后一列信息不可读 | 仅给这两张表增加可聚焦横滑容器，正文、图解、交互与桌面布局保留 |

## 回归路径

- 官网 → 两个精选体验 → 个人素材／问题 → 设置 → 取消返回／保存返回 → 结果 → 本机历史。
- 官网 → 九个品类 → 项目用途筛选 → 参考体验 → 硬件方案 → 成本账本 → 官网。
- 官网 → 两篇文章 → 页内导航／交互 → 返回官网；手机宽表可读到末列。
- 各级深链接、长页面滚动、无 JavaScript、注册表失败、未知地址，均能恢复到有效入口。
- 新浏览器首次直接打开「我的」→ 缓存全部 → 断网 → 首次打开全部 11 条回放；同时验证服务器返回 503 后不会假报完成，恢复后可重试。
- SW 从 v6 升级到 v7，保留同源其他应用的缓存；缓存写入失败不破坏在线读取。

跨页流程由 `tools/product-smoke.mjs` 执行，与已有首页、文章、APP、工作区回归一起进入 Pages CI。浏览器假接口只验证实现行为，不产生付费调用。

## 下一步验收

产品结构与返回路径已连通。下一轮重点应是两个精选体验的真实结果质量和实际设备操作：按 [真实接口验收](app/VERIFY_BROWSER.md) 与 [质量验收包](app/QUALITY_ACCEPTANCE.md) 记录 CORS、权限、播报、用量和账单，再完成物理 iPhone／Android 验收。当前继续保留「待真 Key 验证」，浏览器尺寸模拟不代替实机。
