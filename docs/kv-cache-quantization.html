先看地图：TurboQuant 在量化技术版图中的位置

先花 3 分钟看清三件事：省显存一共有几条路、量化这条路上有哪些方法、TurboQuant 为什么值得了解。

讲人话「量化」= 用更少的格子存数字，省显存。常见的量化方法多数压的是模型本身——发布前压好一次即可；TurboQuant 压的是聊天时不断新生成的「草稿纸」——必须边生成边压、一次压对。难度高得多，这也是长上下文时代真正的显存瓶颈。

显存告急之后：三条不同的技术路线

显存不够，是所有大模型都躲不开的难题。到 2026 年，业界已经形成三条截然不同的路线：

改建筑 · 架构路线 从图纸上就少占地，这条路线走得最远：DeepSeek 从 V2 的 MLA（把 Key/Value 先压成小摘要再存）、V3.2 的 DSA（回头看历史时只挑重点看），再到 2026 年的 DeepSeek-V4——把两种压缩注意力 CSA + HCA 逐层交替叠起来，历史先按段压成摘要，再稀疏地挑着看。结果是百万字上下文成为常规配置：同样 1M 上下文，KV Cache 只有 V3.2 的 10%（Flash 版 7%），相当于传统 BF16 注意力的 2%。效果最彻底，代价是必须在训练阶段就定型，只有模型开发方才能采用。
故事走这条路 压数字 · 量化路线 房子不动，把里面每件家具做小：模型结构一点不改，只把每个数占用的 bit 数从 16 压到 2～4，任何现成的模型都能直接套用。它与架构路线也不是二选一——V4 自己就把 KV 存成 FP8（只有 RoPE 那几维留 BF16），索引缓存用 FP4，等于在新架构之上又叠了一层量化。TurboQuant 就在这条路线上。
挪地方 · 工程路线 显存放不下就先搬到隔壁：offloading 把暂时用不到的 KV 挪去内存、磁盘，再靠前缀缓存复用公共开头，需要时搬回来。空间省下了，代价是来回搬运带来的延迟——通常作为补充手段，与前两条路线配合使用。
一个容易混淆的概念：DSpark 不属于省显存的方法与 V4 同期发布的 DSpark（同系列还有 DFlash、Eagle3）走的是投机解码：先由一个轻量草稿模型连续预测若干个词，再由大模型一次性校验，校验通过的部分直接采用，从而减少大模型的串行步数。它在 V4 的线上服务中把单用户生成速度提高了 60～85%，但并不减少 KV Cache 的占用，额外的草稿模型本身还要再占一部分显存。压缩显存与提升速度是两类不同的优化目标，评估时需要分开看待。

三条路线各解决一部分问题，真实系统中往往叠加使用。下文只沿量化这条路线展开——先认清这条路线上的三大战场。

量化的三大战场

战场一 · 压权重｜最普及

把模型文件压小

权重是静态的：发布前用校准数据慢慢压一次，用户直接下载压好的模型。平时说的「4-bit 模型」多数属于这一类。

GGUF / llama.cpp（本地部署事实标准） GPTQAWQ NVFP4 / MXFP4（4-bit 新格式） NF4 / QLoRA（微调场景）
战场二 · 压计算｜生产标配

让矩阵乘法本身用低精度跑

不光存得小，算得也快：H100 一代原生支持 FP8，DeepSeek-V3 的训练也用了它；到了 Blackwell 一代，原生支持的精度又降到 FP4——V4 的 MoE 专家权重就是 FP4 存的，还专门做了 FP4 量化感知训练。

FP8（数据中心主流） NVFP4（Blackwell 原生） SmoothQuant / W8A8
主角在这里 战场三 · 压 KV Cache｜新战场

压聊天时的「草稿纸」

KV Cache 是动态的：边聊边长，必须即来即压、一次压对，没机会校准重来。上下文一长（百万 token 级），它才是显存占用的主要来源。

FP8 KV（工业界保守做法，省 2×） KIVI / KVQuant（学术 2-bit） TurboQuant（本篇主角，已进 vLLM 主线）
为什么「压 KV Cache」比「压权重」难压权重像出版社印书：开印前有的是时间反复校对。压 KV Cache 像速记员：话音刚落就得记完，记错了没机会改。因此权重量化的常用手段（用数据校准、反复微调）在这里大多无法使用——免校准、在线、一次压对是这个战场的硬门槛，也正是 TurboQuant 的立足点。

TurboQuant 的名片与技术定位

出身：Google Research 2025 年提出（arXiv:2504.19874，已被 ICLR 2026 接收），由 PolarQuant（旋转 + 极坐标量化）和 QJL（1-bit 残差纠错）两个部件组成。

战绩：KV Cache 压到约 3 bit/数几乎无损（KV 显存缩减 6 倍以上），不需要任何训练或校准数据，且理论上逼近失真率下界——在相同比特数下，任何方法都不可能明显比它更准。

落地进展：TurboQuant 已经进入 vLLM 主线，启动服务时通过 --kv-cache-dtype turboquant_4bit_nc 即可启用；AMD 在 2026 年 6 月给出了 MI355X 上的生产级实现，并重写了解码核。

独立评测更保守：Red Hat AI 团队 2026 年 5 月的横向评测显示，4-bit 档才是实用区间（容量约 3.4 倍，精度下降 1～4 分）；论文主打的 3-bit 档在长上下文和高难度推理任务上明显退化，最差下降近 20 分。另有一项代价：它只压缩存储，参与计算前仍需还原成 BF16，吞吐约为 BF16 的 66～80%。

选型参考：显存不紧张时，FP8 KV 仍是默认选择——容量翻倍、代价极低，且能直接用 FP8 张量核参与计算。TurboQuant 的价值集中在显存接近饱和的场景：突发高并发下，BF16 的 P99 首字延迟可达 17 秒，改用它后降到 3.5 秒以内；AMD 的 agentic 多轮测试中，首字延迟从 13.9 秒降到 0.89 秒，吞吐提升 1.63 倍，KV 缓存命中率从 5.3% 升到 67.7%。已知边界是它目前只支持标准 MHA/GQA，尚不支持 DeepSeek 采用的 MLA。

它代表的路线已成主流：「先随机旋转、再量化」这套思路（同类方法还有 QuaRot、SpinQuant）已经从论文走进产品——Meta 官方发布的 Llama 3.2 端侧量化版用的就是 SpinQuant。看懂了 TurboQuant，也就看懂了整个旋转类方法的底层逻辑。

第 0 层 · 入门铺垫

预备知识：四个够用的小概念

故事里会用到一点线性代数。先垫好四块砖，每块约 1 分钟，后面读起来不卡。

讲人话先认识四个词：bit 是存数字用的格子；向量是一排数；内积是给两排数「像不像」打分；正交矩阵是只转方向、不变形状的旋转。先掌握这四个概念就够了。

① 比特与精度

计算机存数字要花「比特（bit）」。n 个比特能表示 2ⁿ 个不同的值：16 bit 能分 65536 档（很精细），2 bit 只能分 4 档（很粗糙）。

大模型的参数原本用 FP16 存，每个数 16 bit。「量化」就是把 16 bit 换成 2～4 bit，代价是精度变粗。

② 向量与内积

一排数就是一个向量。小明 8 门课的成绩单 [85, 78, 92, …] 就是一个 8 维向量。

内积（点积）＝对应位置相乘再求和，衡量两个向量「像不像」：两个学生成绩模式越接近（都理科强、文科中等），内积越大。这是第 5 层的主角。

③ 正交矩阵＝纯旋转

用矩阵乘一个向量，相当于把它「变换」到另一个坐标系。正交矩阵做的变换是纯旋转：不改变长度、不改变夹角，信息一点不丢。

它还有个好性质：逆矩阵＝转置（R⁻¹ = Rᵀ），想转回去非常便宜。这是第 3 层「随机旋转」敢转的底气。

④ 这些在大模型里对应什么

大模型推理时要存两大块数据：权重（模型学到的参数）和 KV Cache（对话过程中缓存的向量）。

它们本质上都是「一大堆向量」——和成绩单一样。所以后面每次出现「小明成绩」，你都可以在脑中替换成「模型里的一个向量」。

第 1 层 · 问题背景

为什么要量化压缩

先感受一下问题有多大，再谈怎么解。

讲人话问题：模型本身占地大、草稿纸又厚，显存装不下。解法：每个数少用格子存。难点：格子少了精度掉，怎么保住？——这就是主线的第 ①② 步。

一个 70B（700 亿）参数的模型，每个参数用 FP16 存要 16 bit，仅权重就需要约 140GB——远超单张 GPU 的显存。这就是部署大模型的头号障碍。

量化压缩（Quantization）：把高精度数值转成低精度表示。比如 16 bit → 2～4 bit，存储直接缩到原来的 1/8～1/4，同时想办法让模型精度尽量不掉。

TurboQuant 的两层核心思想

1. PolarQuant（极坐标量化）
先随机旋转，把数据变到更适合量化的坐标系，再用 Beta 分布特性做最优量化 ＋ 2. QJL（量化 Johnson-Lindenstrauss）

案例：小明的成绩单

故事的主角登场了，后面每一步操作都在它身上进行。

讲人话这个故事拿小明的 8 门课成绩当例子——它就是模型里的一个向量。后面每一步操作都在这份成绩单上进行：看懂它，就看懂了算法。

小明有 8 门课的成绩要存（满分 100）：

语文 85数学 78英语 92物理 88 化学 76生物 82历史 79地理 81

每门课用 16 bit 存，共 8 × 16 = 128 bit。目标：用 2～3 bit/门 实现「近无损」压缩——也就是压完再还原，分数几乎不变。

第 3 层 · 核心机制

第一阶段：PolarQuant 四步压缩

归一化 → 随机旋转 → Lloyd-Max 量化 → 逆旋转重建。点「下一步」跟着数据一步步变。

讲人话四个步骤：归一化（先记住总长度）→ 随机旋转（把分数摊匀）→ 2-bit 粗存（每门课只挑 4 档之一）→ 用时转回来。旋转是关键：摊匀之后，粗存才不伤精度。——主线第 ③④⑤ 步。

深入一层：为什么旋转之后就「适合量化」了？（Beta 分布）

直接看成绩表，数据会在某些方向「扎堆」：理科分都高、文科分都居中——维度之间强相关，分布形状因数据而异，量化边界没法预先算好。

随机旋转（Hadamard 或高斯正交矩阵）把这种相关性打散。数学上可以证明：归一化向量经过随机旋转后，单个坐标的分布收敛到一个固定的 Beta 分布（对称、集中在 0 附近、形状只和维度 d 有关，和你的具体数据无关）。

分布一旦「已知且固定」，就可以离线预先算出最优的量化边界和代表值——这正是 Lloyd-Max 算法做的事：给定分布，找到让均方误差（MSE）最小的分段方案。文档里 [-1,-0.5,0,0.5,1] 的均匀边界是教学简化版，实际按 Beta 分布算出的边界是非均匀的，中间密、两头疏。

深入一层：Lloyd-Max 算法本身在干什么？

它是个交替迭代算法，目标是让「量化误差的平方和」最小：

① 固定各格子的边界，把每个格子的代表值更新为格内数据的条件均值（重心）；
② 固定代表值，把边界更新为相邻两个代表值的中点；
③ 重复到收敛。

你可以把它理解成一维版的 K-Means 聚类。因为旋转后分布已知，这个迭代可以离线做一次、全模型复用，推理时零开销。

深入一层：Hadamard 矩阵为什么是首选旋转？

Hadamard 矩阵的元素只有 +1 和 -1（乘上 1/√d 归一化后正交）。用它做旋转/逆旋转时不需要乘法，只需要加减法，还有 O(n log n) 的快速变换算法（类似 FFT）。这让「旋转」这个额外步骤几乎不增加计算成本，甚至可以融合进矩阵乘法里。

PolarQuant 的存储小账

第 4 层 · 可选增强

第二阶段：QJL 残差纠错

压缩必有误差。QJL 的思路：不存误差的精确值，只存误差的「正负号地图」。

讲人话粗存完总会差一点零头。QJL 不存零头本身，只往几个随机方向投影、记下正负号——每维再花 1 bit，把误差压掉大半。——主线第 ⑥ 步。
先说结论：它是可选的实际生产环境（如 llama.cpp）通常省略 QJL，PolarQuant 单独使用已经足够。这里的原理仍值得展开，第 5 层的修正公式正源于它。

三步走

① 算残差

① 残差：归一化尺度下，原始与重建的差：

+0.02-0.02+0.06+0.04 -0.03+0.03-0.01-0.01

深入一层：JL 引理凭什么保证「只存符号还有用」？

Johnson-Lindenstrauss 引理说：用随机矩阵把向量投影后，向量之间的内积（相似度）关系以高概率近似保持。

也就是说，两个残差向量「像不像」，在投影之后依然「像不像」。再进一步只取符号，虽然每个分量的量级没了，但「方向一致性」的统计信息还在——配合范数（第 5 层会用到），就能把误差的修正量估出来。这是一种「用极少比特保住最关键统计量」的思想。

第 5 层 · 最精妙的一幕

注意力计算：内积的误差与修正

这是 TurboQuant 比其他压缩方法更准的核心，也是 QJL 存的那点符号信息发挥价值的地方。

讲人话注意力只关心内积。符号内积会系统性地把结果低估约 20%，乘上固定系数 1.2533 即可消除这一偏差。这一章解释这个系数的来历。

5.1 为什么要算内积

在成绩场景里，内积就是两个学生的「相似度分数」：

小明 [84, 79, 89, 86, 77, 80, 79, 81]（重建值）
小红 [82, 81, 85, 88, 79, 78, 82, 80]
相似度 = 84×82 + 79×81 + 89×85 + … = 52,847

数值越大，两人成绩模式越像。在大模型里，这个「相似度」就是注意力分数——query 向量 q 和 key 向量 k 的内积 ⟨q, k⟩，决定模型该「关注」哪些信息。注意力算错，模型就看错重点，所以内积精度直接决定压缩方法的成败。

5.2 压缩带来的问题

用重建值算内积得 52,847，但用原始值算的「真实内积」是 53,001——压缩误差传导到了内积上。QJL 的补救思路：我不知道原始值的精确大小，但我记了残差的方向（正负号）。利用「比重建值高一点还是低一点」的统计信息，可以估算出修正量。

深入一层：√(π/2) 这个常数是从哪来的？

对一个标准高斯随机变量 g，只保留符号后，它与自身的相关性会「缩水」：E[g · sign(g)] = E[|g|] = √(2/π) ≈ 0.798。

也就是说，用符号代替真实值算内积，结果会被系统性地乘上一个 √(2/π) 的收缩因子。要让估计无偏（平均意义上不高估也不低估），就要在外面乘回它的倒数——√(π/2) ≈ 1.253。除以 m（投影维度数）则是对 m 个独立估计取平均。这类「符号量化 + 常数校正」的技巧在压缩感知和哈希检索里非常经典。

第 6 层 · 工程视角

反量化：压缩了，用的时候贵不贵？

量化省的是存储，但推理时要把数据「解压」回来用——这一步的成本决定量化是否真的划算。

讲人话「解压」不是重建原始数据，只是查表 + 转回去：代价很小，而且可以和模型本来就要做的计算合并完成。

反量化（Dequantization）是量化的逆过程：把压缩后的低精度数据恢复成可以参与矩阵乘法的高精度数。以成绩为例：

量化等级
[3, 3, 1, 2, 2, 1, 2, 2]（2-bit 整数） 查表 → 代表值
[0.75, 0.75, -0.25, …]（浮点） 逆旋转 → 重建值
[0.68, 0.58, 0.78, …]（原始坐标系）
步骤操作计算成本
① 查表量化索引 → 代表值O(1) / 元素，极低
② 尺度恢复乘以整组共享的范数：x × ‖x‖₂1 次乘法 / 元素
③ 逆旋转（可选）矩阵乘法 R⁻¹·xO(n²) 或 O(n log n)

看起来第 ③ 步最贵，但 TurboQuant 有两个化解办法：

办法一：Hadamard 旋转只需加减法。Hadamard 矩阵元素只有 +1/-1，逆旋转不需要乘法，全是加减，还能走 O(n log n) 快速变换——成本大幅降低。

办法二：延迟反量化。注意力计算时直接在量化空间做内积（正交旋转不改变内积，第 5 层的公式就是在量化空间算的），只在最后一步反量化结果，而不是提前把所有数据解压一遍。算得少，搬得也少。

第 7 层 · 性能收益

性能影响：TTFT 与 TPS 为什么都变快

量化不只是省显存，它直接换来推理速度。理解这一层，要先接受一个反直觉的事实。

讲人话省下的显存换来两件事：同样的卡装得下更长的上下文；读草稿纸的搬运量变小，长文生成反而更快。——主线第 ⑦ 步的前半。

两个指标

TTFT（Time To First Token）

首 token 延迟：从输入 prompt 到吐出第一个字的时间，反映「响应速度」。主要受限于预填充（prefill）阶段——要一口气处理整个输入序列。

TPS（Tokens Per Second）

每秒生成 token 数：反映「生成速度」，决定长文本输出效率。主要受限于解码（decode）阶段——每次只生成一个 token，却要读一遍全部权重。

反直觉的关键：瓶颈不在「算」，在「搬」

大模型推理通常是内存带宽受限而非计算受限——GPU 大部分时间花在从显存把权重读进来，而不是做乘加运算。所以：

FP16 读取量：16 bit × 参数量 → 高带宽压力
2-bit 读取量： 2 bit × 参数量 → 8× 带宽节省

再加上缓存友好性：70B 模型 FP16 要 140GB，塞不进任何单卡；2-bit 后约 18GB，可以常驻高端 GPU 显存，大幅减少数据搬运。

指标量化前（FP16）量化后（2-bit）
TTFT内存带宽受限，权重加载慢8× 带宽节省，加载快；Hadamard 旋转可融合进矩阵乘法，额外开销很小
TPS权重可能溢出缓存，每步都从主存重读权重常驻缓存，避免反复搬运
反量化开销无极小（查表 + 乘法，可并行，几乎不加延迟）
实测结论TurboQuant 在保持模型精度的同时，推理速度可提升 2～4 倍；显存越紧张的设备，收益越明显。
