## 方案延迟横评（待实测）

同一场景（如「孩子问一个问题到听到回答」）下，不同技术架构串起来端到端的实际延迟差异，是选型最直观的决策依据。以下表格框架先列出，具体数值待实测补齐（附 Demo）。

| 方案链路 | 首包延迟 | 端到端延迟 | 并发承载 | 语义打断 | Demo |
|---|---|---|---|---|---|
| 裸模型串接（ASR → LLM → TTS，请求-响应） | 待测 | 待测 | 自行限流 | 不支持 | 待补充 |
| 裸模型串接（ASR → LLM → TTS，流式） | 待测 | 待测 | 自行限流 | 弱支持 | 待补充 |
| 百炼多模态交互开发套件（全双工套件方案） | 待测 | 待测 | 平台托管 | 原生支持 | 待补充 |
| Qwen-Omni 端到端（语音进语音出） | 待测 | 待测 | 平台托管 | 原生支持 | 待补充 |
| 端云协同（端侧唤醒 + 端侧 ASR + 云端 LLM/TTS） | 待测 | 待测 | 混合 | 视端侧实现 | 待补充 |

**测试口径规划**：

- **首包延迟**：从用户结束说话到首字节音频返回的时间
- **端到端延迟**：从用户结束说话到听到完整回答的时间
- **并发承载**：单账号下可同时维持的连接数
- **语义打断**：用户中途插话时的响应表现
- **测试语音样本**：统一 3~5 句短问答，覆盖轻度 / 中度 / 复杂三档

> 🧪 **Demo 位置**：对应可运行 benchmark 脚本将放到 [`benchmark/`](./benchmark/)（TODO），可复现表格中数字。测试机、网络环境、时间点等前置条件将写在 demo README。

## 怎么读

每个方案页是**跨品类**的横切视图，回答三个问题：

1. **能力地图**：方案能力清单 / 价位 / SLA / 适合的场景
2. **品类适配**：在 6 个品类中分别如何落地（链接到 `solutions/0X-xxx/02-solution.md`）
3. **典型 BOM 与计费**：本方案接入后端云成本量级

## 贡献新方案

新增方案的步骤：

1. 在本目录新建 `0X-<方案名>.md`
2. 按"能力地图 → 品类适配 → BOM/计费"三块写
3. 在对应品类的 `solutions/0X-xxx/02-solution-<方案>.md` 中补充具体接入代码（可选）
4. 提 PR
