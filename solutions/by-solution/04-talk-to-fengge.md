# Talk-to-Fengge 开源案例 — 架构启发

> ⚠️ 这不是商业方案，而是一个开源案例，仅作为 **架构启发** 参考。
>
> 项目地址：[github.com/YeJe-cpu/talk-to-fengge](https://github.com/YeJe-cpu/talk-to-fengge)（MIT 协议）

## 1. 项目简介

Talk-to-Fengge 是一个开源的「实时语音对话 + 声音克隆 + 人格注入」端到端系统。第一个 Demo 是与 B 站百万粉博主「峰哥亡命天涯」的 AI 分身进行实时语音对话。

核心特点：用 15–45 秒音频即可复制声音，结合人格系统还原说话风格与口头禅，工程延迟小于 1 秒。

## 2. 架构 / 技术栈

| 层次 | 默认实现 | 可替换方案 |
|---|---|---|
| 实时音视频 | LiveKit（WebRTC） | — |
| STT | Cartesia ink-whisper | — |
| LLM | MiniMax-M2.7-highspeed | DeepSeek / Gemini |
| TTS + 声音克隆 | VoxCPM（开源，需 GPU ≥ 8GB） | MOSS-TTS（CPU）/ Cartesia Sonic（云端） |
| 人格系统 | 「女娲 Skill」蒸馏 + 直播转写 | — |
| 记忆系统（可选） | OpenViking | — |

数据流：用户说话 → STT → LLM（人格 + 记忆检索）→ TTS 声音克隆 → 用户听到回复

## 3. 架构启发

对硬件品类方案开发者的参考价值：

1. **WebRTC 实时音频链路**：演示了如何在浏览器 / 端侧通过 LiveKit 达到类电话级别实时对话
2. **声音克隆 + 人格分离**：声色与人格是独立模块，架构上可分别替换——这对玩具陪伴、桌宠、AI 耳机等品类有直接参考意义
3. **多 Provider 可切换设计**：通过 `.env.local` 即可切换 LLM / TTS 提供商，体现了「模型无关」的工程理念
4. **端云延迟工程**：工程延迟 < 1 秒，实际网络约 2–3 秒；对低延迟要求场景有参考

## 5. 局限性

- 需要多个 API Key / 服务，暂无一键部署
- 前端较简（粒子特效单页），无数字人形象
- 记忆系统效果取决于对话量
