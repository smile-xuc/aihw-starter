## 方案总览

桌宠品类的核心诉求是「语音 + 表情 + 动作」三路同步输出，叠加情感陪伴与学习辅助的持续黏性。与纯语音设备不同，桌宠需要在每次推理中同时决策「说什么 + 做什么动作 + 什么情绪」，并通过日积月累的记忆系统让每台设备都成为用户的专属伙伴。

**方案分层**：

| 层次 | 方案 | 说明 |
|---|---|---|
| 基础链路 | 标签嵌入式（方案 C） | LLM 单次推理输出文本 + emoji + action + emotion，端侧流式解析驱动多路外设 |
| 黏性层 | 每日记忆日记系统 | 自动提炼对话记忆点，生成陪伴日记，支持长期记忆召回 |
| 网络兜底 | BLE Opus 代理对话 | Wi-Fi 不可用时通过手机蓝牙透传完成完整 AI 对话 |
| 运营层 | 云端 Agent 配置后台 | RAG 知识库 + Prompt 编排 + 意图管理 + A/B 实验，零代码热更新 |

## 二、推荐 AI 链路

### 2.1 输出协议选型

桌宠品类推荐**方案 C · 标签嵌入式**——token 消耗最低，端侧嵌入式设备易于解析：

| 维度 | 方案 C · 标签嵌入式 | 方案 A · 标准 JSON | 方案 B · 自然语言符号 |
|---|---|---|---|
| 输出格式 | `[emoji-01][action-01]哎呀` | `{"action_query":[...],"response":"..."}` | `["举右",2],["抓取","苹果"]。我将…` |
| Token 消耗 | 最低 | 中 | 中 |
| 流式 TTS | 支持（去标签后直出） | 需等完整 JSON | 最快 |
| 端侧解析 | 简单正则 | JSON 反序列化 | 自定义分隔符 |
| 适用设备 | 桌宠/毛绒/AI 眼镜 | 多自由度机械臂、复杂参数 | 工业/服务机器人 |

### 2.2 端到端链路

```
端侧（屏 + 舵机 + RGB + 麦克风）
        │
        │ WebSocket 流式
        ▼
千问 LLM（一次推理输出 文本 + emoji + action + emotion）
        │
        ├─► 文本流 → 标签解析器 → 触发屏幕表情、舵机动作、RGB
        │
        └─► 文本（去标签后）+ emotion → 情感 TTS（CosyVoice v3-plus/flash）
```

### 2.3 接入前置

| 项目 | 说明 |
|---|---|
| 服务开通 | 百炼控制台开通 Qwen 系列 + cosyvoice-v3-plus 或 cosyvoice-v3-flash |
| API-KEY | 标准 sk- 前缀 |
| SDK | dashscope（Python/Node.js/Java），TTS 走 WebSocket |
| 端侧 | 屏幕、舵机/马达、RGB 任一组合，需固件层做标签解析 |

## 三、本地能力（离线可用）

端侧语音识别 + 本地动作执行，不依赖网络连接。

### 3.1 唤醒与端侧语音指令

支持唤醒词打断机制（设备播报/执行中可随时通过唤醒词打断），端侧指令覆盖 8 大类约 45 条：

| 类别 | 代表指令 | 说明 |
|---|---|---|
| 运动类 | 前进 / 后退 / 左转 / 右转 / 转圈圈 / 巡逻 | 四足协调运动 |
| 姿态类 | 立正 / 趴下 / 握手 / 睡觉 / 摆个造型 | 静态姿势切换 |
| 特技类 | 倒立 / 俯卧撑 / 翻跟斗 / 跳一跳 | 高难度表演 |
| 舞蹈/律动 | 摇摆 / 刨土 / 跳个舞 / 游泳 / 旋风腿 | 14 种律动组合 |
| 互动类 | 抱一抱 / 亲一个 / 打招呼 / 秀一个 | 情感互动 |
| 表情/情绪 | 发火 / 卖萌 / 撒娇 / 开心 / 害羞 / 惊讶 | 屏幕表情 + 肢体联动 |
| 声音模拟 | 唱首歌 / 学狗叫 / 学猫叫 | 预置音效 + 动作 |
| 系统控制 | 安静点 / 开始配网 / 调大音量 / 打开蓝牙 | 设备管理 |

### 3.2 触摸交互

通过背部触摸传感器检测触摸次数（1.5 秒时间窗口内），差异化响应：

| 触摸次数 | 响应 |
|---|---|
| 1 次 | 打招呼（语音 + 动作 + 开心表情） |
| 2 次 | 挠痒痒 / 撒娇（随机触发） |
| 3 次 | 生气发火（语音 + 动作 + 愤怒表情） |

### 3.3 对讲通话（PTT）

按住头部对讲按键 → 组群内实时语音 → 松开停止发送。需设备已联网且加入对讲群组。

## 四、云端 AI 能力

### 4.1 AI 对话

| 能力 | 说明 |
|---|---|
| 天气 / 新闻查询 | Function Calling 调用外部 API |
| 多轮上下文 | 对话会话内保持上下文理解和记忆 |
| 情感陪伴 | 情绪疏导、兴趣倾诉、成长鼓励 |
| 百科问答 | 常识性问题、计算、翻译 |

### 4.2 意图识别与多指令控制

云端 AI 将自然语言映射为本地动作指令集中的一个或多个指令，支持组合顺序执行。典型场景：

- "给我表演一个节目" → 打招呼 → 跳个舞 → 摆个造型
- "做个俯卧撑然后跳一下" → 俯卧撑 → 跳一跳

### 4.3 对话情绪识别

AI 实时分析对话情绪倾向（9 种：开心 / 伤心 / 愤怒 / 害怕 / 害羞 / 惊讶 / 卖萌 / 撒娇 / 发火），联动设备三路输出：

- 屏幕表情切换
- 灯光颜色与动画（如开心→暖黄呼吸、伤心→蓝色低亮）
- 机器人微动作

### 4.4 学习辅助

覆盖 11 项学习功能，适配 3-14 岁：

英语陪读（跟读 + 发音纠正）、编故事、讲笑话、写作文引导、成语接龙、古诗记忆、汉语拼音、数学启蒙、生活常识、安全知识、科普知识。

### 4.5 性格体系

支持预设性格影响 AI 对话语气和行为倾向：

| 性格 | 对话风格 | 行为倾向 |
|---|---|---|
| 平和 | 语气平稳，表达温和理性 | 动作舒缓，情绪稳定 |
| 温柔 | 语气亲切，用词柔和 | 动作轻柔，偏爱卖萌/撒娇 |
| 暴躁 | 语气夸张，表达活泼 | 动作幅度大，易触发发火/惊讶 |

性格通过 APP 或语音指令切换，影响 System Prompt 中的性格描述片段和 LLM Temperature 参数。

## 五、每日记忆日记系统

让设备逐步"记住"用户，持续累积情感联结。核心价值：每台桌宠都是用户独一无二的专属伙伴。

### 5.1 核心机制

**记忆提炼流程**：

```
每日对话 → 云端实时标记候选片段(后台异步,不中断对话)
         → 每日结束时 AI 摘要提炼 → 结构化记忆卡片
         → 定期合并 + 权重衰减(近期/高频记忆权重高)
```

**记忆维度**：

| 维度 | 示例 |
|---|---|
| 兴趣偏好 | "喜欢恐龙""最近在学钢琴" |
| 情绪事件 | "今天考试没考好，心情低落" |
| 重要人物 | "好朋友小明""妈妈今天生日" |
| 生活事件 | "明天要去动物园""刚转到新学校" |
| 学习进展 | "正在背乘法口诀""英语学到颜色单词" |
| 互动偏好 | "最喜欢让桌宠跳舞""经常让桌宠学猫叫" |

### 5.2 记忆召回

AI 在对话中智能检索已有记忆，使交互更有连续性：

- 兴趣关联：提到"动物"时主动关联之前聊过的恐龙
- 情绪关怀：记得昨天心情不好，今天主动问候
- 事件跟进：之前说"明天考试"，第二天主动询问结果
- 学习延续：上次学了 5 个英语单词，今天先复习再学新内容
- 纪念日提醒：记住生日，到期主动送祝福

### 5.3 陪伴日记生成

每日自动生成结构化日记（以桌宠第一人称视角撰写，风格温暖亲切，与当前性格匹配）：

> **2026-04-08 · 桌宠的日记**
>
> 今天和小主人聊了 23 分钟！小主人告诉我最喜欢的恐龙是霸王龙，还问了好多关于恐龙的问题。后来说明天要考数学，有点紧张，我给加油打气啦。还让我跳了 3 次舞，每次都笑得好开心。
>
> 今日心情指数：开心 ⭐⭐⭐⭐ | 互动次数：17 次 | 最爱动作：跳个舞

### 5.4 长期用户画像

基于累积记忆构建兴趣画像、性格特征、学习阶段等档案 → 影响 AI 对话策略（对内向用户更主动引导话题）、推荐学习内容、个性化互动反馈。

### 5.5 百炼实现方案

| 环节 | 推荐实现 |
|---|---|
| 记忆提炼 Prompt | 百炼应用编排，配置专用提炼 Prompt 模板（定义维度权重 + 粒度） |
| 记忆存储 | 云端用户档案（主存储）+ 设备 Flash 缓存摘要（离线召回） |
| 记忆召回 | RAG 检索，对话前注入 memory_context 变量到 System Prompt |
| 日记生成 | 百炼应用模板，类似"智能学情总结"（输入当日对话 → 输出结构化日记） |
| 衰减与合并 | 每周/每月自动归纳，高频/近期权重高，过时记忆弱化 |

## 六、BLE Opus 蓝牙代理对话（网络降级方案）

确保在任何网络环境下都能完成 AI 对话，消除 Wi-Fi 依赖带来的体验断点。

### 6.1 系统架构

```
┌─────────────────┐    BLE (Opus)    ┌──────────────┐   4G/5G/Wi-Fi   ┌─────────────┐
│   桌宠设备端    │ ◄──────────────► │   手机 APP   │ ◄──────────────► │ 云端 AI 服务 │
│                 │  蓝牙音频双向     │              │   HTTPS / WSS   │             │
│ · 麦克风采集    │                  │ · BLE 接收   │                  │ · ASR       │
│ · Opus 编码    │                  │ · Opus 解/编 │                  │ · LLM       │
│ · 扬声器播放    │                  │ · 云端通信   │                  │ · TTS       │
│ · 端侧唤醒     │                  │ · 指令下发   │                  │ · 意图识别   │
└─────────────────┘                  └──────────────┘                  └─────────────┘
```

### 6.2 触发与切换

| 场景 | 机制 |
|---|---|
| 配网失败降级 | Wi-Fi 连续 3 次配网超时 → 自动进入 BLE 广播等待配对 |
| 断连降级 | Wi-Fi 断连 > 30 秒，自动尝试 BLE 回连 |
| 自动回切 | BLE 模式下检测到 Wi-Fi 恢复 → 自动切回直连 |
| 手动切换 | 语音指令"蓝牙对话"或 APP 内点击切换 |

### 6.3 技术规格

| 参数 | 规格 |
|---|---|
| BLE 版本 | 4.2+（推荐 5.0） |
| 传输协议 | GATT，自定义 Service + Characteristic |
| 连接间隔 | 7.5ms - 15ms（低延迟音频） |
| MTU | ≥ 247 字节 |
| Opus 上行 | 16kHz / 16-24kbps / 20ms 帧 / Mono / VOIP 模式 |
| Opus 下行 | 16-24kHz / 24-32kbps / 20ms 帧 / Mono |
| 额外延迟 | 相比 Wi-Fi 直连约 +0.5～1 秒 |

### 6.4 BLE 模式下的能力范围

BLE 代理模式下除对讲通话外全部功能可用（AI 对话、意图控制、情绪识别、学习辅助、性格体系、记忆日记），本地语音指令和触摸交互始终可用（不依赖网络）。

## 七、云端 Agent 配置后台

面向运营 / 产品 / 算法团队的一站式可视化 AI 配置平台，实现零代码热更新（配置变更到设备生效 ≤ 30 秒，无需 OTA）。

### 7.1 核心模块

| 模块 | 能力 |
|---|---|
| RAG 知识库 | 多库隔离（儿童百科/安全教育/古诗词/英语等），支持 PDF/Word/TXT/网页抓取，混合检索 + Rerank |
| Prompt 编排 | 可视化编辑器 + 变量插值（user_name/personality/memory_context/rag_context），版本管理 + Diff + 回滚 |
| 意图与技能 | 意图 CRUD + 训练样例句管理 + 冲突检测，可视化拖拽式动作时序编排 |
| 性格与情绪 | 性格参数（Prompt 片段 + Temperature + 动作权重），情绪映射表（灯光/微动作/阈值） |
| 内容安全 | 多级敏感词库 + 年龄分级（3-6/7-10/11-14 岁）+ 处置策略 + 拦截日志 + 告警 |
| 记忆管理 | 提炼规则配置、衰减策略、日记生成模板、异常记忆清理 |
| 模型路由 | 多模型注册 + 场景路由 + 降级策略 + 成本监控预警 |
| 版本发布 | 配置快照 + 灰度发布（按设备百分比/分组）+ 一键回滚 |
| A/B 实验 | 流量分配 + 核心指标对比 + 统计显著性 + 自动报告 |
| 数据看板 | DAU/MAU、对话数据、功能使用 TOP 20、AI 质量指标、网络模式分布 |

### 7.2 对话日志分析

支持对话逐轮回放（脱敏）、Bad Case 标注（答非所问/幻觉/不适龄/过短）、热门话题聚类，标注数据可导出用于 Prompt 优化或模型微调。

### 7.3 Function Calling / 工具注册

注册外部 API（天气/新闻/词典等），定义参数 Schema（JSON Schema），配置调用策略（自动识别/关键词触发/强制），支持 Mock 调试。

## 八、关键参数与硬约束

### 8.1 标签解析必须流式做

LLM 输出是 token 流，标签 `[emoji-01]` 可能跨多个 token 才完整。客户端需在收到完整标签后再触发动作，否则会出现「还没说完话就先动了」的错位。

### 8.2 标签数量限制

每次回复建议最多 1 个 emoji + 1 个 action。否则 LLM 倾向堆叠标签，端侧动作排队执行体验变差。

### 8.3 情绪 TTS 适配音色

cosyvoice-v3-plus / cosyvoice-v3-flash 支持 7 种情绪。仅部分音色支持情感参数：龙安欢、龙安洋、龙呼呼、龙火火、龙川叔。其他音色传入情绪参数会被忽略。

### 8.4 安全兜底

用户表达自伤、暴力意图时，强制走 neutral 语气，避免 TTS 念出愤怒/悲伤的不当播报。这条建议直接写入系统提示词。

### 8.5 非功能性指标

| 维度 | 目标 |
|---|---|
| 端侧语音指令响应 | 唤醒到执行 ≤ 1 秒 |
| AI 对话首字延迟（Wi-Fi） | ≤ 2 秒 |
| AI 对话首字延迟（BLE） | ≤ 3 秒 |
| BLE 单向音频延迟 | ≤ 200ms |
| BLE 配对成功率 | ≥ 98%（10 米内） |
| 唤醒准确率 | ≥ 95%（安静环境 1 米） |
| 误唤醒率 | ≤ 2 次/24 小时 |
| 续航（Wi-Fi） | ≥ 2 小时（中等使用） |
| 续航（BLE） | ≥ 2.5 小时 |
| 日记生成时效 | 对话结束后 ≤ 5 分钟 |

## 九、接入步骤

### 9.1 设计阶段

1. 列出硬件支持的所有「动作」和「表情」，编号（如 `action-01` 到 `action-10`）
2. 制定标签到端侧执行的映射表（见 10.1）
3. 在系统提示词中明确告知 LLM 可用标签集

### 9.2 开发阶段

1. LLM 调用使用流式输出（`stream=True`）
2. 在 token 流上跑标签解析器，标签触发端侧动作，剩余文本送 TTS
3. TTS 调用根据 LLM 输出的情绪标签设置 `emotion` 参数

### 9.3 联调阶段

- 端侧设置动作最大时长（防堵转）
- 同标签设最小冷却（默认 1 秒，防抖动）
- 表情持续到下一句话开始

### 10.3 流式标签解析（Python，可移植到嵌入式）

```python
import re

PAT = re.compile(r'\[(emoji|action)-(\d{2})\]')
EMOTION_PAT = re.compile(r'<M>(\w+)</M>')

def stream_handler(token_stream, screen, motor, tts):
    buf = ""
    emotion = "neutral"
    emotion_set = False

    for token in token_stream:
        buf += token

        if not emotion_set:
            m = EMOTION_PAT.search(buf)
            if m:
                emotion = m.group(1)
                emotion_set = True
                tts.set_emotion(emotion)
                buf = EMOTION_PAT.sub('', buf)

        for m in PAT.finditer(buf):
            kind, code = m.group(1), m.group(2)
            if kind == "emoji":
                screen.play(f"emoji_{code}")
            else:
                motor.enqueue(f"action_{code}")

        clean = PAT.sub('', buf)
        tts.feed(clean)
        buf = ""
```

## 十一、能力边界

- **能做**：单次推理同时输出文本 + 表情 + 动作 + 情绪四路；端侧并行驱动；记忆系统长期累积；BLE 降级全功能可用
- **不能做（当前）**：复杂多自由度机械臂连续轨迹（建议走 JSON 格式 + 客户自建运动规划层）
- **建议自建的部分**：动作连贯性平滑（IK 解算、舵机加速度限制）、长期人格一致性（走 Agent 后台的长记忆 + RAG 注入）、APP 端日记展示（日历/时间线视图）
