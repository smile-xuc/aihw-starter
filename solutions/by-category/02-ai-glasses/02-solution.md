## 方案总览

```
眼镜端                          云端
┌─────────────┐               ┌──────────────────────────────┐
│ 麦克风阵列    │               │ 多模态交互开发套件（底座）      │
│ 摄像头       │   BLE/Wi-Fi   │  ASR + LLM + VL + TTS        │
│ 扬声器       │ ────────────► │  全双工对话 / 视觉问答 / 指令   │
│ [光波导显示]  │  (经手机App   │──────────────────────────────│
│ 端侧SoC:     │   或直连)     │ 附加项（按需叠加）              │
│  VAD/唤醒    │               │  🌍 livetranslate 同传        │
│  拍照压缩    │               │  📞 omni-flash-realtime 音视频 │
│  蓝牙传输    │               │  📝 听悟 录音转写               │
└─────────────┘               └──────────────────────────────┘
```

**分工原则**：大模型推理全部在云端；端侧做三件事——VAD/唤醒（省电省流量）、拍照压缩、蓝牙传输链路优化（见第六节）。

**两条接入路线**：

| 维度 | 套件路线（推荐起步） | 单点直连路线 |
|---|---|---|
| 集成粒度 | 端到端打包（ASR+LLM+VL+TTS+端侧 SDK） | 按能力直连各模型 API |
| 端侧能力 | 内置 VAD / 回声消除 / 语音唤醒 | 自己实现 |
| 对话模式 | 全双工流式可打断 | 按 API 协议自行组织 |
| 系统覆盖 | Android / iOS / Linux / RTOS | 云端 / 移动端为主 |
| 配置方式 | 控制台可视化（模型/提示词/知识库/指令） | 写代码 |
| 适用 | 快速量产、目标含 RTOS、团队以硬件为主 | 已有成熟软件栈、追求极致体验或深度定制 |

两条路线不互斥：常见组合是**套件承载基础对话与视觉问答，同传/实时音视频/听记按需单点直连**。

## 一、底座：多模态交互开发套件

面向硬件设备的工程化封装，解决端侧接入大模型的「最后一公里」——尤其是 RTOS、嵌入式 Linux 这类自行拼链路成本很高的平台。

### 1.1 能力清单

| 模块 | 内容 |
|---|---|
| ASR | 流式识别 + 端侧 VAD + 回声消除 + 语音唤醒 |
| LLM | Qwen 系列默认，可替换平台其他大模型 |
| 视觉 | 拍照问答（Qwen-VL），内置文物讲解、地标识别、药品识别、热量分析等场景模板 |
| TTS | 超拟人音色 + 一句话声音复刻 |
| 设备指令 | 预置指令集 + 可视化自定义（「拍张照」→ `cmd_camera_capture`） |
| 配置面 | 控制台可视化：模型 / 提示词 / 知识库 / Agent / 插件 / 指令 |

### 1.2 接入步骤

**控制台路径**：

1. 千问大模型控制台 → 应用 → 「多模态交互开发套件」官方应用
2. 可视化配置：模型、系统提示词、知识库（上传文档）、Agent/插件、设备指令
3. 选择「智能眼镜」场景模板
4. 调试台用网页麦克风测试对话效果 → 发布

**端侧 SDK 集成**（以 Linux 为例）：

```bash
git clone https://github.com/aliyun/alibabacloud-bailian-speech-demo
cd alibabacloud-bailian-speech-demo/linux
# 按 README 配置 API-KEY 和应用 ID
make && ./demo
```

集成到产品固件的关键步骤：

1. SDK 初始化时传入 API-KEY 和应用 ID
2. 启动音频采集，将 PCM 流送入 SDK
3. SDK 回调返回：识别文本、LLM 回复、TTS 音频流、设备指令
4. 端侧根据回调执行播放、显示（显示款出字幕）、控制动作

**RTOS 集成要点**：

- SDK 提供精简版本，内存占用与芯片平台相关；音频缓冲区容量需按实际码率显式配置，默认值通常偏小
- WebSocket 协议要求设备支持 TLS
- 建议先在 Linux 上跑通逻辑，再移植到 RTOS

### 1.3 「一看即懂」链路（底座核心场景）

```
用户：「这是什么菜？」（注视菜单）
  → 端侧：唤醒 + 拍照 + 压缩（见第六节）
  → 蓝牙传至手机 App → 上传云端
  → 套件：Qwen-VL 识别 + LLM 组织回答
  → TTS 流式回播：「这是泰式冬阴功汤，酸辣口味…」
  → 显示款同步在镜片显示要点文字
```

> 🧪 可运行示例：[`demo/kit-chat/`](./demo/kit-chat/) — 图片 + 问题 → 视觉理解 → 语音播报的最小闭环

### 1.4 端侧芯片方案参考

三档形态对应不同的芯片组合（信息来自公开报道与拆解，供选型参考）：

| 形态档位 | 芯片组合 | 公开代表 | 说明 |
|---|---|---|---|
| 音频眼镜 | 蓝牙音频 SoC（杰理、恒玄 BES2700 级），兼跑端侧唤醒 | 华为智能眼镜等 | 结构上接近 TWS 耳机方案 |
| 拍照眼镜 · 入门 | 低功耗 Wi-Fi/ISP 芯片（如泰芯 TXW81X 级）+ 杰理蓝牙音频 | 白牌/入门产品 | 成本优先，MJPEG 编码 + Wi-Fi 直传 |
| 拍照眼镜 · 高端 | 恒玄 BES2800 主控 + 独立 ISP（如研极微） | 理想 Livis（公开报道，1699 元，歌尔联合研发） | 放弃通用高算力 SoC，低功耗主控 + 外挂 ISP，控制算力冗余与成本 |
| 拍照眼镜 · 旗舰 | 高通骁龙 AR1 主控 + 恒玄协处理（低功耗待机） | 小米 AI 眼镜（AR1 + BES2700） | AR1 承担视觉与高清拍摄，协处理芯片负责音频与全天候待机 |
| AI 显示眼镜 | 高通骁龙 AR1 级主控（+ 协处理双芯） | Rokid Glasses（AR1）、千问 AI 眼镜（AR1 + BES2800） | 显示渲染与视觉处理需要更高端主控 |

对接云端方案的含义：端侧唤醒由蓝牙/主控芯片承担（不消耗云端资源）；ISP 能力决定图片压缩质量与速度，直接影响「一看即懂」链路时延（见第六节）；套件 SDK 的 RTOS 精简版可运行于恒玄级平台，AR1 级平台可走 Android/Linux 完整版。

## 二、附加项 A：🌍 同声传译（qwen3.5-livetranslate-flash-realtime）

**场景**：面对面跨语言对话、出国点餐问路、外语会议旁听。音频款走「翻译语音进耳朵」，显示款叠加「字幕上屏」。

**接入要点**：

| 项目 | 说明 |
|---|---|
| 模型 | `qwen3.5-livetranslate-flash-realtime`，WebSocket 实时协议 |
| 输入 | 流式音频（16k PCM），自动识别源语言 |
| 输出 | 目标语言的翻译文本流 + 语音流，可同时消费（音频播报 + 字幕显示） |
| 音色 | 当前仅支持 Tina 音色，产品设计勿承诺自选音色 |
| 断句 | 模型内置语义断句，端侧无需自行切分 |

**产品实现建议**：

- 双向翻译做成「对话模式」：镜腿触控切换我说/对方说，或用双麦克风波束区分声源
- 显示款把译文按行推送到光波导（单绿屏适合短句字幕，控制单行字数）
- 时长计费特性决定它是「功能包」候选，默认不常开（见 [03-cost.md](./03-cost.md)）

## 三、附加项 B：📞 实时音视频交互（qwen3.5-omni-flash-realtime）

**场景**：「给 AI 打电话」——按住镜腿即问即答，摄像头开启后 AI 实时看你所见，边走边聊。当前交互延迟最低、体验规格最高的形态，适合旗舰档产品。

**与套件基础对话的差异**：

| 维度 | 套件基础对话 | omni-flash-realtime |
|---|---|---|
| 视觉输入 | 拍照（单帧图片） | 连续视频流 |
| 交互延迟 | 秒级 | 亚秒级，「打电话」级流畅度 |
| 打断 | 支持 | 原生全双工，随时插话 |
| 成本 | 低（按次调用） | 高（按时长持续计费） |
| 定位 | 性价比路线，全档位适用 | 高性能路线，旗舰档/演示场景 |

**接入要点**：

- WebSocket 实时协议，音频与视频帧按协议分通道推送
- 视频帧无需高帧率——1 fps 上下即可支撑「看见你所见」的体验，帧率每翻一倍成本近似翻一倍
- 会话时长直接决定成本，产品上用「按住说话/通话计时」的交互明示用户，避免无感长连接

> 🧪 可运行示例：[`demo/omni-realtime/`](./demo/omni-realtime/) — 实时语音 + 图像帧的双向流式对话

## 四、附加项 C：📝 录音转写（听悟）

**场景**：会议听记、课堂笔记、访谈记录——眼镜一键开录，会后出结构化纪要 + 待办 + 分角色发言。

**接入要点**：

| 项目 | 说明 |
|---|---|
| 产品 | 通义听悟（tingwu）API |
| 输入 | 录音文件（离线转写）或实时音频流（实时转写） |
| 输出 | 转写文本、说话人分离、章节摘要、待办提取 |
| 链路建议 | 眼镜录音 → 手机 App 上传 → 听悟离线转写 → App 内呈现纪要 |

**产品实现建议**：

- 离线转写链路成本远低于实时链路，「会后 3 分钟出纪要」的体验对听记场景已足够
- 录音涉及他人声音，需在产品层做录音提示（指示灯/提示音）并在隐私政策中明示
- 该能力与录音卡品类（07）同源，眼镜是形态迁移，商业模式可参照其 SaaS 订阅路径

## 五、附加项集成方式：套件承载 vs 单点直连

| 附加项 | 经套件集成 | 单点直连 |
|---|---|---|
| 🌍 同传 | 套件应用内配置翻译智能体（简单场景） | livetranslate API（推荐，功能完整） |
| 📞 实时音视频 | — | omni-flash-realtime API（仅此路线） |
| 📝 听记 | — | 听悟 API（仅此路线） |

选择标准：基础对话 + 视觉问答走套件（开发量最小）；三个附加项中，同传轻量场景可留在套件内，重体验产品建议全部单点直连，由业务后端统一编排。

## 六、端云协同：图片上行链路优化

眼镜的端云分工不是「端侧跑模型」，而是**让图片更快到云端**——推理全在云端，端侧优化传输链路。这是「一看即懂」体验达标（目标：从提问到开始播报 3 秒内）的工程关键：

| 环节 | 优化手段 | 效果量级 |
|---|---|---|
| 拍照 | 场景自适应分辨率：识别类 720p 足够，OCR 类 1080p；避免无脑原图 | 数据量降 50–80% |
| 压缩 | 端侧 JPEG 质量 70–80 + 中心裁剪（视觉问答关注中心区域） | 再降 30–50% |
| 传输 | BLE 双通道/大 MTU 协商；图片走 Wi-Fi Direct 或 BT Classic，控制信令走 BLE | 传输耗时从秒级降至百毫秒级 |
| 上行 | 手机 App 转发时直传 OSS（就近接入点），云端取 URL 而非透传字节流 | 降低 App 转发时延与失败率 |
| 复用 | 会话内多轮追问复用已上传图片（传 URL 引用），不重复上传 | 追问延迟接近纯文本 |

配套体验设计：拍照后立即播报承接语（「让我看看…」）掩盖传输耗时；弱网时降档压缩优先保通率。

## 七、能力边界

- **能做**：Android / iOS / Linux / RTOS 全覆盖、全双工对话、拍照视觉问答、同传（音频+字幕双输出）、实时音视频交互、离线/实时转写、可视化配置
- **不能做（当前）**：端到端延迟的量化 SLA 承诺（需在客户硬件实测）、livetranslate 自选音色（仅 Tina）、特定芯片白名单（建议售前联调）
- **建议自建的部分**：端侧拍照压缩与蓝牙传输策略、录音提示与隐私同意流程、功能包付费开关与设备配额管理
